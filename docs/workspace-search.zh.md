# 目录搜索实现与边界

目录搜索在应用进程内运行，使用 Conan 管理的 PCRE2 10.49，不依赖外部 grep 程序或 Rust 工具链。Conan 根配方使用 `force=True`，使 Qt、GLib 和 Muffin 解析到同一个 PCRE2 版本；因此依赖升级后需要重新构建相关包。

## 读取与匹配

- 最多四个工作线程按文件分配任务，实际数量受 CPU 核数和查询配置限制。每个线程独立持有 PCRE2 的表达式、匹配数据和资源限制。
- 普通文本搜索采用滚动窗口，默认读取块为 64 KiB。窗口保留模式长度和上下文，支持跨块命中；UTF 解码、CRLF/CR 归一化、代理对和 UTF-16 位置都跨块保持连续。
- 小文件使用编辑器已有的编码检测。较大文件流式支持 UTF-8，以及带 BOM 的 UTF-16/UTF-32；不能可靠解码的内容会在详情中列出，避免当作没有命中。
- 正则保留当前文件搜索的 PCRE2 语义，包括跨行、环视、捕获组和零宽匹配。任意跨行正则需要连续文本，因此独立限制输入大小，避免声称所有正则都能使用固定大小的窗口。
- 已打开笔记的内容覆盖磁盘；大笔记复制不可变 PieceTable 快照交给后台，输入过程中不会在界面线程复制整篇文本。

## 结果、跳转和替换

结果仅保留路径、UTF-16 范围、行号、短上下文和归一化文本的 SHA-256 指纹，不保留完整文件或捕获组。点击结果时校验当前文档指纹，变化后要求重新搜索。流式结果发布保持串行，界面只接收排队的更新。

替换预览按需重新读取文件，检查指纹、匹配范围和编码往返一致性，再逐项生成替换内容。只按需读取引用的捕获组视图，不累计保存每个命中的完整捕获文本；展开后的替换文本也有独立预算。写入仍使用原有备份、日志、原子提交和恢复机制。搜索成功不代表该文件满足批量替换条件。

默认资源边界：

| 项目 | 限制 |
| --- | --- |
| 普通搜索单文件 | 512 MiB，同时受文件打开保护设置限制 |
| 正则搜索单文件 | 32 MiB；打开缓冲区按 UTF-16 占用计算 |
| 搜索匹配数量 | 10,000 |
| 保留结果的上下文和命中记录预算 | 16 MiB；并非整个进程的内存上限 |
| 替换输入单文件 | 8 MiB |
| 替换预览累计数据 | 64 MiB |

达到匹配或结果预算会明确标记结果不完整，禁用批量替换。摘要提供已搜索文件数量，点击“搜索详情”可查看过大、读取/编码失败、冲突、搜索期间变化、正则资源限制及固定忽略目录。固定忽略规则暂未迁入设置。

## 验证与性能测量

`MuffinWorkspaceSearchTest` 覆盖 Unicode 编码、解码/匹配边界、换行归一化、零宽与跨行正则、并行全局预算、未保存快照、预览过期校验、原格式替换与恢复，以及 100 MiB 文件搜索。

可在 Release 测试程序上对真实目录或单个文件分别测量一线程和四线程的首条结果时间、总耗时及保留上下文大小：

```powershell
.\build\Release\MuffinWorkspaceSearchTest.exe --benchmark G:\github\Muffin\build\prose_100mb.md '第 11041 回'
```

性能依赖文件系统缓存、存储设备、表达式及结果数量，不能根据依赖库名称推断加速倍数。

2026-10-22 本机 Windows Release 测量（编译结束后执行，文件系统缓存未清空）：

| 数据集 | 一线程 | 最多四线程 | 首条结果 |
| --- | --- | --- | --- |
| 10,000 份约 2 KiB 的笔记，命中 100 个文件 | 4.73 秒 | 2.26 秒 | 约 0.10 秒 |
| `prose_100mb.md` 的独立目录副本，104,361,814 字节，命中 19 处 | 第一次 1.15 秒 | 第二次 0.69 秒 | 完成该文件时发布 |

单个文件实际只分配一个工作线程；两次大文件测量的差异包含缓存影响，不能解释成线程加速。独立测量程序的峰值工作集分别约 22.4 MiB（万文件）和 19.7 MiB（大文件），不是完整编辑器的内存指标。两组结果只保留约 4.6 KiB 上下文，此外还有命中记录、路径和指纹。
