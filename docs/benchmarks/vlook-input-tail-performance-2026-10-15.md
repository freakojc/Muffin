# 1 MiB 连续输入：重复投影查询与记录开销对照

本轮减少了一处可重复的累计开销：菜单刷新中的格式状态和图片状态共用一次编辑投影，并在智能标点设置读取中复用单个局部 QSettings。**偶发长尾尚未解决，真实 Windows 输入及完整六组 GUI 验收也未完成。** 完整数据见[诊断 JSON](vlook-input-tail-diagnostic-2026-10-15.json)。

## 输入与测量条件

沿用固定 1 MiB 单页文档、VLOOK Fancy Dark、Noto Serif、Qt 6.11.1、窗口 1100×820、视口 1086×761、96 DPI、DPR 1。每个新进程顺序执行 80 次输入、左右移动和上下移动，各间隔 50ms。GUI/窗口链路诊断与构建、测试不并发。

修改前后各两轮，每轮三种记录模式：`off` 关闭产品 perf scopes 和主题阶段计时；`minimal` 保留聚合计时；`detailed` 增加 Qt 事件、线程 CPU/cycles 和脏区时间线。全部仍保留基准的输入/绘制时钟、心跳和工作集采样，因此 off 也不是零观测开销。它们都由独立线程投递 Qt 操作事件，**不经过真实 Windows 键盘输入队列**。

本轮发现 Qt 的 active/exposed 标记不足以证明桌面可接收输入。computer-use 连接连续失败，重置后仍无法初始化；带保护的原生输入基准读取 Windows 前台句柄连续为 **0**，因此 **未发送任何按键**。只读元数据显示进程在 session 2、WinSta0/Default，input desktop 可打开；仅凭这些信息无法进一步断定是锁屏、远程会话还是其他桌面问题，没有切换桌面或修改系统策略。

修改后的六份诊断均记录 `windows_foreground=false`，修改前六份缺少该观察（unknown）。前一轮只检查 Qt 状态的旧记录也不能倒推为已经验证 Windows 前台。因此本轮**不把这些记录当作真实手感、原生 GUI 验收或稳定性能改善比例**。它们用于验证同一合成处理链路中的工作量、计时组成与记录开销。完整原始样本、失焦记录、所有异常与四份原生输入阻止记录均保留。

修改前第二轮 minimal 有 6 次实际变化输入等待 ≥100ms，最长约 **280ms**。修改后第一轮 detailed 有 **15 次**，最长 **766.92ms**，原始样本 index 68：

| 时间点（相对阶段起点） | ms |

| 实际投递 | 3430.94 |

| 处理结束 | 3784.73 |

该样本同步 **39.20ms**，实际投递到派发 **314.60ms**，处理后到 paint **398.26ms**，paint **14.15ms**。该阶段输入处理最大约 **47.27ms**、局部解析最大约 **15.96ms**；等待区间仍处理多个后续输入、状态刷新与窗口更新，线程 CPU/cycles 继续增长。没有一个同样长的单次 parse/paint 解释整个等待。

将后续输入 handler 区间与 Qt 事件区间一起裁剪到“本次处理结束 → paint 开始”，取区间并集后，可以进一步解释累计时间，不能只统计 Qt notify 日志而漏掉独立 OperationEvent：

| 样本 | 处理后至 paint | 后续输入数 / handler 区间并集 | Qt 事件区间并集 | 二者合并覆盖 | 未覆盖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 上轮约 370ms，index 28 | 198.49ms | 5 / 156.94ms | 22.96ms | **179.90ms** | 18.59ms |
| 本轮约 767ms，index 68 | 398.26ms | 11 / 348.74ms | 5.12ms | **353.86ms** | 44.39ms |

两次最慢操作开始时，后面已有 **2/6 次输入**实际投递到合成队列。可确认的是：处理后至 paint 的约 **91%/89%** 墙钟区间，被后续输入处理与 Qt 事件覆盖，主要不是一段完全空白的等待。handler 自身可能被线程调度打断，因此区间覆盖不等于 CPU 执行时间；剩余未覆盖时间也没有指定阻塞原因。原始参考样本和逐次覆盖统计保存在同一 JSON 中，嵌套区间没有重复累加。

这一结果把下一步收敛到投递方式与累计处理，而不是对整段时间笼统归因于系统调度。Qt 合成事件积压期间仍可继续排在异步绘制前面；真实 Windows 输入是否出现相同模式，必须在可用前台继续对照。本轮没有改变产品事件优先级或强制 repaint 来跳过这些等待。

没有重新尝试上轮被本机策略阻止的 WPR，也没有精确 ready 时间/调度栈。尤其当前 Windows 前台不可用，不能将合成队列的等待全部解释为用户真实键盘输入的系统调度延迟，也不能据此调整产品事件优先级或插入强制 repaint。

## 已实现的热点修复

此前每次菜单上下文捕获分别调用格式查询和图片查询，两者都通过 BlockEditContextResolver 重建相同光标位置的行内投影。现在 EditorController 提供一次性 `CursorCommandState`：用同一 BlockEditContext 计算六种格式及图片地址，MainWindow 在一次刷新中消费这些值。结果不跨光标、文档或设置变更持久缓存，没有新增失效规则或 AST 常驻。

原有独立格式/图片 API 仍可调用，两者与共享查询使用相同格式语义；多块/多文本节点选择仍不产生统一格式状态，图片保持按焦点查询。独立 HTML 图片块只读取其块切片，移除了为查找该标签而 materialize 整份 PieceTable 的路径。编辑和渲染投影的智能标点设置各用一个局部 QSettings，设置仍在每次投影构建时读取，没有额外长期缓存。

## 草稿完成与内存

新增 `draft.deliverCompletion` 将 worker 完成后的 GUI 通知单独计时；不包含后台文件编码/写入。四份详细输入记录中该通知最大约 **0.005–0.011ms**。修改后异常轮草稿入队 **0.0644ms**、snapshot 请求 **0.2122ms**、完成通知 **0.0086ms**，均不足以解释 767ms 停顿。尚不能排除 worker 并发 CPU 或存储竞争，只能排除这一已记录通知本身长时间占用 GUI 的说法。

结束时基准通过正常草稿请求路径提交最新版本，再以异步定时检查等待确认（60 秒超时），不在输入路径调用 waitForDone。十二份记录最终均确认 **82/82**。数据保留等待耗时和排空后的工作集；本轮初版未带版本号的 drain 记录是在最终截图编码后取值，等待时间也包括这段截图开销，不能视为纯保存等待。后续 schema 2 改为在截图前记录，两种口径明确区分。请求发出当下仍可能占用 worker 临时缓冲，不能把阶段末工作集直接当成排空值。

off 两轮排空后工作集约 **336.8/346.5 → 339.1/338.5MiB**，minimal **344.5/336.6 → 338.9/342.3MiB**，detailed **357.6/356.5 → 349.3/353.1MiB**。没有一致下降，不据此宣称压缩了文档内存或排除了泄漏。详细 trace 自身会保留事件 JSON、CPU 样本等数据，内存不能与 off 混作产品常驻缓存对照。

另补 1 MiB/8 次和 30 MiB/4 次的 schema 2 功能检查，原始记录保留在 JSON 的 `tool_smoke` 中。30 MiB 检查在结束请求最新草稿后异步等待 **103.14ms**，最终确认 **6/6**，排空后工作集约 **1312MiB**；1 MiB 确认 **10/10**。这些检查验证结束时的保存和确认路径，仍未通过 Windows 前台条件，不计入 GUI 延迟或内存改善验收。

## 原生输入与后续验收

手动基准增加 `MUFFIN_GUI_NATIVE_INPUT=1`，仅测 80 次 `x`，通过 Windows SendInput 虚拟键 down/up 进入原生输入队列；这仍是软件注入，不是物理键盘/IME 验收。每次发送前必须确认基准窗口是 Win32 前台，QKeyEvent 处理钩子分别记录实际开始/结束，检查数量、文本与额外输入。失焦或发送失败则停止注入、标记不完整，绝不改发到另一个应用。本轮由于前台句柄为 0，没有完成该路径的实际发送验证。

PS 运行器和矩阵汇总新增前台、原生输入完整性、草稿排空检查；Qt active/exposed 仍独立保留。旧记录没有新字段的检查边界保持原样，新输入诊断汇总将缺失前台字段标为 unknown/不可验收。完整 **1/10/30 MiB × 单页/三页** GUI 矩阵未在已知无前台窗口的环境中反复运行；需恢复稳定交互桌面后补齐，所有旧记录继续保留。

下一步先在可用前台完成原生键盘与相同合成投递对照，确认积压是否跨投递方式存在；然后细分最坏输入区间的排版、行内样式和窗口刷新。此轮减少了日常累计工作，没有声称根治此前 370ms 或本轮 767ms 的长尾。

独立复核保留的 **18 份**原始记录（含两份功能检查）、**432 个**主诊断分位数，并以另一套端点扫描算法核对 **1040 条**输入至绘制区间覆盖统计；确认所有前台条件无效的记录均未被接受为 GUI 验收。Python/PowerShell 语法、基准 C++ 格式和 `git diff --check` 通过。

完整 Release 构建通过，完整 CTest **339/339** 全绿（**444.99 秒**），日志 `build/input-tail-release-build.log`、`build/input-tail-all-ctest.log`。`dist` 已刷新，三个应用二进制 SHA-256 与 Release 一致，见 `build/input-tail-dist.log`、`build/input-tail-dist-hashes.json`。后续只调整测量工具及文档；产品代码未再修改。本轮未提交、未推送。
