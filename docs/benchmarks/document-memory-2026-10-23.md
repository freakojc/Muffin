# 三类 Markdown 文档的内存重测与 AST／索引压缩

日期：2026-10-23。产品基线为 `3b9246ec`，已包含此前的资源生命周期修复。本轮先测基线，再修改产品代码，再测相同样例。原始数据见 [JSON](document-memory-2026-10-23.json)。

## 测量方法

Release、Windows Qt QPA、原生文字后端、真实 `MainWindow`，窗口 1000×700，缩放系数 1、96 DPI。独立临时设置，使用默认主题、实时编辑模式，禁用自动更新与自动保存。三种内容各生成约 1 MiB、10 MiB 的 UTF-8 文件，每个组合在修改前、后各运行两个新进程，共 24 次。样例分别是中文段落、包含强调／链接／列表／表格的格式密集内容，以及单个多行 C++ 代码围栏。

内存采样线程每 5 ms 记录工作集和私有提交。打开并处理界面事件后等待 2 秒，再以 100 ms 间隔读取 10 个稳定样本；每次进程取稳定样本中位数，表格再取两次进程的平均值。工作集峰值使用 Windows 记录的进程历史峰值，私有提交峰值使用采样最大值，后者可能漏掉短于采样间隔的尖峰。打开时间只记录至解析完成并处理界面事件，未独立探测首屏 Paint，不能视为精确首帧延迟。

采样期间没有并行构建或 CTest。文件在测量前生成，系统文件缓存温热；未测冷磁盘、网络文件、多标签或多主题。固定内容的重复样例用于比较数据结构，不能代表所有笔记；尤其 1 MiB 已是较大的普通笔记。两次重复不足以推断总体分位数。容量清点在采样结束后执行，避免统计集合自身污染内存数据。

## 进程结果

单位均为 MiB；每格为 **修改前 → 修改后**。工作集表示当前驻留内存，私有提交包含进程承诺使用的私有内存，二者不能相加。

| 文档 | 工作集峰值 | 稳定工作集 | 私有提交峰值 | 稳定私有提交 |
| --- | ---: | ---: | ---: | ---: |
| 中文笔记，1 MiB | 198.45 → 198.79 | 198.45 → 197.35 | 98.52 → 99.65 | 98.44 → 98.53 |
| 格式密集，1 MiB | 234.64 → 232.62 | 234.64 → 232.62 | 132.78 → 131.15 | 132.78 → 131.15 |
| 长代码块，1 MiB | 323.12 → 320.31 | 323.11 → 320.31 | 218.40 → 217.89 | 218.40 → 217.89 |
| 中文笔记，10 MiB | 273.56 → 271.53 | 248.80 → 229.29 | 181.17 → 180.86 | 161.47 → 143.03 |
| 格式密集，10 MiB | 537.10 → 535.36 | 492.03 → 451.17 | 447.68 → 449.23 | 412.08 → 368.87 |
| 长代码块，10 MiB | 1411.68 → 1404.89 | 1411.68 → 1404.89 | 1381.87 → 1372.79 | 1381.87 → 1372.79 |

10 MiB 中文笔记与格式密集文档的稳定私有提交分别降低约 **11.4%**、**10.5%**。长代码块降低约 **0.7%**。1 MiB 中文笔记的绝对进程数值未出现稳定收益：固定启动开销与分配器波动足以覆盖小样例的数据结构节省。

打开峰值没有明显改善，格式密集样例的私有提交峰值甚至略增；不能把稳定占用下降解释为解析峰值问题已经解决。10 MiB 长代码块仍有约 1.34 GiB 稳定私有提交，需要单独优化块内布局。

## 数据结构结果

64 位构建的 `InlineNode` 从 **104 字节降至 88 字节**。源码首尾仍使用 32 位常规坐标；内容首尾、开闭标记使用相对于对应源码边缘的 16 位差值。长文本只要标记邻近边缘，同样可以紧凑表示。`-1` 缺失标记保留独立哨兵；宽坐标、过大差值、特殊负值均退回已有的完整 `qsizetype` 坐标存储。改变某个范围仍保留其他范围的独立语义。

`PieceTable` 的四个换行／词首索引使用 `CompactOffsetIndex`，普通偏移每项 4 字节，超过 `quint32` 范围时提升为 `qsizetype`，不截断。底层仍是 Qt 隐式共享容器，后台准备和快照复制保持独立修改语义。查询仍使用二分查找，没有按字数／行数的线性解码。

cmark 转换时先计数，再一次预留行内子节点数组，减少扩容分配、节点搬移和长期保留的空闲容量。没有为每个叶子增加独立堆对象。

10 MiB 样例的容量清点，单位 MiB：

| 内容 | AST 行内数组等容量 | 文本索引容量 | 已清点总容量 |
| --- | ---: | ---: | ---: |
| 中文笔记 | 30.71 → 15.66 | 5.00 → 2.50 | 58.41 → 40.86 |
| 格式密集 | 153.74 → 130.30 | 18.00 → 9.00 | 232.96 → 200.53 |
| 长代码块 | 约 0 → 约 0 | 18.00 → 9.00 | 58.00 → 49.00 |

以上按共享缓冲去重，包含对象及数组容量，不包含分配器头部、完整 Qt／字体／文字整形内部对象等，因此不能与进程数值直接相加。前后 12 对记录的文件 SHA-256、字符／行／词计数、块／行内节点数、共享文本节点数、可选元数据与字符串容量，以及布局清点完全一致。

长代码块仅有极少 AST 节点，其容量清点远小于进程占用。实现上 `LiteralTextLayout` 会为整个代码块逐物理行创建并保留 `TextLayout`、视觉行和行号信息；当前块级懒布局不能进一步限制这个单块内部的驻留量。这是后续应优先处理的方向，本轮未改变其排版行为。

## 复现

分别在保留相同诊断入口的基线和优化工作树运行；当前代码生成的是优化后的数据。`before`、`after` 只是输出目录名，不会自动切换产品版本。

```powershell
cmake --build --preset conan-release --target MuffinDocumentTabsTest
python scripts/benchmark_document_memory.py --output build/document-memory-before
# 应用优化后，使用另一目录保存结果：
python scripts/benchmark_document_memory.py --output build/document-memory-after
```

脚本从 Conan 预设取得 Qt 运行环境；`--repeats` 默认 2。手动入口为 `MuffinDocumentTabsTest --document-memory`，不自动加入常规 CTest 的内存阈值断言。

回归覆盖紧凑差值及哨兵边界、完整宽度坐标、部分范围修改、复制独立性、索引提升与隐式共享快照，以及已有随机编辑和位置参考测试。
