# VLOOK 冷区域滚动与缓存驻留优化（2026-10-15）

本轮优化新区域的 CSS 匹配、可见区排版和缓存驻留。六组原生 GUI 对照中，冷滚动同步 p95 从 211–235 ms 降至 20–38 ms，计划时刻到视口绘制完成 p95 从 5.5–7.9 秒降至 89–405 ms。长文档的输入、上下移动和空闲回收仍有长尾，不能据此宣称全部交互已经流畅。

对照基线为 [上一轮原生 GUI 报告](vlook-native-gui-performance-2026-10-15.md)；本轮全部逐次输入、阶段计时、分位数、工作集和缓存数量保存在 [原始 JSON](vlook-cold-scroll-performance-2026-10-15.json)。旧基线保持不变。本轮日期按 Asia/Shanghai（UTC+8），各次运行时间戳为 UTC。

## 改动与根因

- 最终样式按完整匹配规则、继承输入和根状态共享，交互配方按完整八状态输入共享；哈希只选择候选桶，完整输入必须相等。每个元素保留独立动画时间线。
- 初次实施共享后，冷滚动 CSS 实际求值次数已经为零，但 CSS 路径仍累计约 10 秒。单独开启 `muffin.perf.css` 后，定位到新元素的选择器筛选约占 8.98 秒；规则查询包含这部分，累计约 9.11 秒。指纹和最终结果查找分别约 225/274 ms；这些嵌套计时不能相加。
- 将只按标签筛选规则的索引改为按完整目标元数据缓存候选选择器：标签、ID、语义类、属性名、伪元素及原始元素。递归预筛 `:is()`/`:where()` 的必要条件，完整匹配器继续检查属性值、祖先、兄弟、位置、否定和交互状态，保留规则顺序与 specificity。
- 滚动同步构建可见区及上下 80 px，停滚 120 ms 后再预取上下各 1.5 屏。每批最多两个块，4 ms 预算在块之间检查；新滚动重置等待，每批读取最新视口，隐藏视图停止预取。
- 普通流式 lazy 布局空闲时保留最多 64 个详细顶层块，可见预取区、光标、选区端点和编辑中的 HTML 块受保护，必要时可超出。释放远处详细布局及其行内样式身份，保留实测高度、位置索引、AST 和结构导航；共享语义树快照仍被持有时不删除其元素。Eager/导出和根格式化上下文维持原行为。
- 最终样式和 cascade/value memo 限制为 2048 项/桶；目标候选和匹配结果池限制为 512 个键/桶；共享配方最多 512 项。变量指纹保留 128 个 Qt 共享表快照。这些是数量边界，不是整个进程的字节级内存预算。

## 对照条件

沿用上一轮的 Windows 原生 QPA、实际 `MainWindow`/`DocumentTab`/`EditorView` 和应用绑定，六组分别用新进程顺序运行，没有并发构建或测试。核对两轮 CSS SHA-256、Qt 版本、字体、窗口/视口尺寸、DPR、DPI、刷新率、样本数和操作节奏均一致：Qt 6.11.1，Noto Serif 16 px，1100×820，96 DPI，DPR 1；i7-10700、8 核 / 16 线程、64 GiB RAM。

本轮最初两次 1 MiB 单页尝试未通过结束窗口状态校验，已排除，留在本地 `build/cold-scroll-gui/`。正式六组使用 `MUFFIN_GUI_PIN_WINDOW=1` 将临时基准窗口置顶，继续要求开始激活、结束激活和暴露；这是相较基线的一项桌面测量条件变化，不修改产品窗口行为。置顶仅减少遮挡干扰，边界校验仍不代表连续追踪每次操作的焦点状态。CSS 深层计时在正式六组中关闭。

每个连续阶段仍为 80 次操作，输入/方向键间隔 50 ms，滚动/后续切页间隔 100 ms，交替切换主题 12 次、间隔 1500 ms。输入为 Qt 合成事件，绘制完成是 QWidget 绘制事件结束，包含排队，不是物理输入至显示器呈现的延迟。使用 nearest-rank 分位数；80 次的 p99、12 次主题切换的 p95/p99 均等于最大值。每种配置只有一轮有效运行，表格不提供总体尾延迟保证。
