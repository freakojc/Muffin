# VLOOK 原生 GUI 连续操作测量（2026-10-15）

本轮测量实际 `MainWindow`、`DocumentTab`、`EditorView` 和应用命令绑定。六种配置分别使用新进程，顺序运行，期间没有并发构建或测试。主要问题是新区域滚动的同步样式/排版工作和排队、已有视口的文字绘制，以及主题切换的全量更新。普通按键的同步耗时已经较低，但仍可能等待很久才能完成绘制。

完整逐次输入、分位数、阶段计时、工作集和隐藏视图事件保存在 [JSON 数据](vlook-native-gui-performance-2026-10-15.json)。这是本机诊断基线，本轮未修改编辑器运行逻辑。

## 环境与测量口径

- Windows 11 Pro for Workstations 26100，Intel Core i7-10700（8 核 / 16 线程），约 64 GiB 内存；Release，Qt 6.11.1，原生 `windows` QPA。
- 窗口 1100×820，DPR 1，96 DPI；屏幕报告刷新率为 32 Hz。单标签页视口 1086×761，三标签页视口 1086×723，差异来自标签栏。
- VLOOK Fancy Dark 固定 CSS 的 SHA-256 为 `dc9ce7c464f4ddf8644040fb77c7c7e408a70f1bee3ba2c9f9a8ac746901f3cc`；正文 Noto Serif，16 px，100% 缩放。主题切换在内置 GitHub 与该 VLOOK 之间交替。
- 沿用前轮的混合行内 Markdown 段落生成器，ASCII 文件达到目标大小后停止，因此略大于 1/10/30 MiB。三标签页配置中每份文档均为该大小，并各自保留会话和 AST。
- 每次运行使用独立设置和临时文档，自动保存、自动更新关闭；正常动画、光标、词数/大纲和恢复草稿定时器保留。基准程序复用应用源码与资源，省略词典和 `main()` 的平台集成。
- 独立生产线程定时向 Qt GUI 事件队列投递操作，避免 GUI 阻塞时生产线程也停止、掩盖排队。每个连续阶段 80 次：输入与方向键间隔 50 ms；滚动和已应用主题的标签切换间隔 100 ms。主题切换 12 次，间隔 1500 ms；隐藏页首次应用主题有 2 次。
- **同步处理**：操作在 GUI 线程开始执行到返回，包含实际按键、滚轮、标签栏鼠标事件或主题 QAction 的应用处理。
- **计划时刻到绘制完成**：操作预定投递时刻至其返回后的首个编辑视口 `Paint` 事件完成，包含生产线程抖动、GUI 排队和绘制。合并输入可以共享同一帧；若操作内部同步触发绘制，则记录该操作内最后一次视口绘制。JSON 另有实际投递到分发、分发到绘制、生产抖动和单帧耗时。
- 输入为 Qt 合成事件，经过真实应用绑定；不包含 Windows 硬件输入分发。绘制完成指 QWidget 绘制事件完成，不代表 DWM 合成或显示器呈现。没有测量端到端物理输入延迟。
- GUI 心跳间隔 8 ms；独立线程每 20 ms 采样 Windows 工作集。启用现有性能作用域和日志，计时会包含这些诊断开销。工作集不是堆大小，最高采样值不是保证捕获的峰值。
- 使用 nearest-rank 分位数。80 个样本的 p99 等于最大值，12 次主题切换的 p95/p99 也等于最大值；每个目标主题只有 6 次。不能据此估计稳定的总体尾延迟。每种配置保留一轮合格运行，不将不同配置当作重复试验。

开始测量时检查窗口激活与暴露，结束时记录并由汇总工具校验。1 MiB、30 MiB 三标签页各有一次末尾失焦运行，已排除并补测；一次补测在初始化激活检查处退出，没有计入样本。原始排除记录留在本地 `build/*-inactive.json`。窗口激活检查是边界检查，不是对每次操作的连续焦点追踪。

## 阶段拆分与后续顺序

1. **先处理冷区域的同步工作量和排队。** 每组 80 次冷滚轮操作累计触发约 4.5–4.7 万次 CSS 实际求值，CSS 独占约 9.6–10.2 秒。30 MiB × 3 中，布局独占约 2.38 秒，80 次操作只产生 7 次视口绘制，其余被合并，积压期间心跳延迟超过 4 秒。`EditorView::scrollContentsBy()` 同步执行 `ensureVisibleBuilt()`，一般在视口上下各预取 1.5 屏；绘制入口也会补齐可见范围。下一轮应优先限制单次同步构建的工作量，先保障实际可见区域，将可中断的预取交给空闲时间，并检查新块样式/配方的复用和驻留上限。需要维持锚点、点击几何及快照隔离正确性。
2. **再优化已有视口的文字绘制。** 热滚动 CSS 实际求值为零，布局独占累计小于 0.3 ms；80 次绘制中，单帧均值约 50–53 ms，p95 约 54–61 ms。文字占已计时绘制子阶段约 88–92%，背景和阴影占比较小。30 MiB × 3 的文字累计 3683 ms，背景 102 ms，阴影 37 ms；应继续细分 `TextLayout::draw()` 的可见行、行内片段、字形绘制和缓存失效，而不是从阴影开始重复优化。
3. **主题切换检查活动页的全量更新。** 在每 1.5 秒交替选择主题的负载下，同步 p95 约 1.4–2.9 秒，30 MiB 绘制延迟 p95 超过 5 秒。30 MiB × 3 的 12 次切换中，CSS 独占累计约 9.01 秒，计数器 7.32 秒，布局 2.28 秒；隐藏页没有执行对应排版。后续拆分活动页快照、全量计数器建立和首视口样式；不要把排队延迟当作一次 CSS 文件解析时间。
4. **继续保留普通编辑长尾与内存对照。** 复现 30 MiB 单标签页额外视口求值，补各缓存驻留数量和字节统计，并在优化后按相同节奏复测六组。现有 GUI 样例补充此前 offscreen 单次测量，不能直接用两者之差推断优化退化。

本轮没有新增 GUI 延迟门禁，也没有放宽已有性能断言。延迟对桌面状态、诊断开销和本机环境敏感，先保留原始分布，再用相同环境下的重复测量评估改进。

## 复现

```powershell
cmake --build --preset conan-release --target MuffinGuiPerformanceProbe
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_gui_performance.ps1
python scripts/summarize_gui_performance.py build/gui-performance build/gui-performance/summary.json
```

PowerShell 的 `ExecutionPolicy Bypass` 仅用于本次脚本进程。程序需要交互桌面，会显示自己的临时窗口；测量时保持该窗口激活。运行器和汇总工具拒绝末尾失去激活/暴露状态的数据，可通过 `-SizesMiB 30 -TabCounts 3` 单独补测。默认结果、日志和窗口截图位于 `build/gui-performance/`；本轮实际输出到 `build/`，汇总时使用对应目录。

该目标 `EXCLUDE_FROM_ALL`，不进入常规构建和 CTest；直接调用方式为 `MuffinGuiPerformanceProbe.exe output.json MiB tabs [samples=80]`，Qt DLL 和插件环境由 PowerShell 运行器从 Conan presets 设置。

本轮手动目标和 Release 完整构建通过，完整 CTest **339/339** 通过（444.00 秒），`dist` 三个应用二进制的 SHA-256 与 Release 一致。汇总工具校验六组窗口状态、阶段和绘制覆盖；从逐次样本独立重算的同步、排队与绘制分位数一致。构建、测试和打包日志分别为 `build/native-gui-release-build.log`、`build/native-gui-all-ctest.log`、`build/native-gui-dist.log`。
