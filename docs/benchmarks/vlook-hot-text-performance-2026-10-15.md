# VLOOK 热视口文字绘制优化（2026-10-15）

本轮让宿主文字绘制只提交实际颜色变化，复用已经保留的字符格式与字形布局。基线采用[上一轮六组原生 GUI 测量](vlook-cold-scroll-performance-2026-10-15.md)，另补一组带文字绘制输入计数的有效 1 MiB 单页[原始基线](vlook-hot-text-before-2026-10-15.json)。

## 根因与改动

`InlineLayout::buildTextLayout()` 已保留 Qt 的字形缓存。GUI 每帧通过 `BlockPaintState::css` 传入采样宿主样式，`InlineLayout::paint()` 会为继承宿主颜色的各段创建临时 foreground selections，即使当前颜色与排版时的基础颜色相同。Qt 6.11.1 的 `QTextLayout::draw()` 逐个构建覆盖区域并处理对应文字行；相同颜色也会走这条路径，已有字形缓存无法省去这些重复绘制与裁剪。

当采样宿主颜色等于基础颜色时，现在直接使用保留的字符格式；发生真正的 hover/focus/动画变色时，继续提交相应覆盖，并保留行内独立颜色与描边覆盖。所有主题共用这一逻辑。字体、塑形、换行和光标几何继续来自原布局。

这也解释了前几轮 offscreen 与 GUI 绘制耗时的差距：部分 offscreen 绘制没有提供 CSS 交互上下文，宿主样式也就没有触发上述重复覆盖。后续对照须同时保留真实 GUI 路径和纯排版/绘制路径的测量条件。

## 诊断与对照口径

手动 GUI/theme probe 新增 `text_paint_work`，由 opt-in、thread-local 的 `themeTextPaintStats()` 提供：

| 字段 | 口径 |
| --- | --- |
| `calls` | `TextLayout::draw()` 调用数 |
| `lines` | 每次调用的完整布局行数之和 |
| `format_ranges` | 每次调用的静态字符格式段数之和 |
| `selection_ranges` | 每次调用的临时绘制覆盖段数之和 |

这些是输入数量，不能据此推导实际可见行数、字形数或栅格 pass 数。计数随阶段重置，普通产品运行默认关闭；绘制时间继续由已有 Text 阶段作用域测量。

补充基线仅增加上述诊断计数，保留修复前的绘制逻辑。一次末尾失焦尝试已排除，留在本地 `build/hot-text-before/`；有效补测位于 `build/hot-text-before-valid/`。

正式对照沿用原生 Windows QPA、实际 MainWindow/DocumentTab/EditorView、固定 VLOOK Fancy Dark CSS、Noto Serif 16 px、1100×820 窗口、96 DPI/DPR 1、32 Hz 屏幕报告刷新率及相同输入节奏；1/10/30 MiB × 1/3 标签页各自使用新进程顺序运行，期间没有并发构建或测试。本轮及补充基线均使用临时基准窗口置顶，并保留开始激活、结束激活/暴露检查。与上一轮相比，新增文字输入计数，其他既有诊断继续启用。

使用 nearest-rank 分位数，每个连续阶段 80 次输入；输入/方向键每 50 ms，滚动/后续切页每 100 ms，主题交替 12 次、每 1500 ms。输入为 Qt 合成事件，绘制完成是 QWidget paint 事件结束，包含排队，不代表物理输入至显示器呈现。p99 在本轮 80 次样本中等于最大值，12 次主题切换的 p95 也等于最大值；每种配置一轮有效样本，保留分布用于诊断。

正式对照中 10 MiB 单页有三次末尾失焦尝试，均已排除并保存在 `build/hot-text-gui/*-inactive*.json`。用户保留基准窗口在前台后，剩余四组顺序补测通过。失焦数据不进入 [六组原始数据与汇总 JSON](vlook-hot-text-performance-2026-10-15.json)。窗口校验是边界检查，不是对每次输入焦点的连续追踪。

## 热滚动结果

每格为上一轮 → 本轮；时间单位 ms。每阶段 80 次滚轮输入，六组各有 80 次视口绘制。

| 每份文档 × 标签页 | 单帧绘制 p95 | 计划到绘制 p95 | Text 阶段独占累计 |
| --- | ---: | ---: | ---: |
| 1 MiB × 1 | 52.5 → 15.0 | 56.6 → 22.3 | 3539.6 → 748.2 |
| 1 MiB × 3 | 55.6 → 14.3 | 67.2 → 19.1 | 3630.1 → 725.0 |
| 10 MiB × 1 | 54.2 → 15.0 | 58.5 → 19.4 | 3659.4 → 744.3 |
| 10 MiB × 3 | 55.3 → 19.5 | 63.0 → 24.6 | 3582.8 → 767.1 |
| 30 MiB × 1 | 59.0 → 19.8 | 63.2 → 24.6 | 3656.9 → 780.0 |
| 30 MiB × 3 | 57.0 → 18.3 | 61.6 → 22.5 | 3604.0 → 727.8 |

Text 阶段累计下降约 79–80%；单帧绘制 p95 下降约 65–74%。1 MiB 单页的补充基线与本轮具有完全相同的 TextLayout 绘制输入量：648 次 draw、3,208 个布局行、54,416 段静态格式；动态覆盖从 **16,008 → 0**，Text 累计从 **3,697.0 → 748.2 ms**。其他五组的热滚动动态覆盖也为零。这一输入对照排除了“少画了部分块/文字调用”作为该样例主要收益来源。

未将单帧耗时换算为屏幕 FPS：本轮没有测量 DWM 呈现，滚轮采样也只按 100 ms 产生一次输入。

热绘制收益没有消除所有操作长尾：

- 30 MiB 单页上下移动的绘制 p95 从上一轮约 99 ms 增至 376 ms。该阶段单帧绘制 p95 约 13 ms，但心跳最大额外延迟约 239 ms；`input.keypress` p95 约 38 ms，行内投影/块刷新 p95 约 37 ms，预取最大不足 0.1 ms，CSS 实际求值为零。需要继续追踪 GUI 排队和投影重建，并以重复试验判断稳定性。
- 1 MiB 三页主题切换同步 p95 从约 363 增至 506 ms；30 MiB 两组从约 938 增至 1257–1270 ms，计划到绘制也从约 1.0 秒增至 1.35–1.38 秒。主题切换主体仍是快照、计数器和布局，文字优化不保证这些阶段的收益。30 MiB 两组的 12 次切换中计数器独占累计约 5.60/5.62 秒，CSS 约 1.70/1.69 秒，与上一轮仍属相近量级；不把单轮最大值变化直接归因到某个新函数。
- 普通输入同步 p95 约 25–36 ms，30 MiB 仍接近 50 ms 的生产间隔。后续优先拆分行内投影/块重建和 GUI 的其他定时工作，再优化活动页全量主题更新。

## 正确性

新增回归比较静态宿主采样与无临时覆盖时的完整像素，验证实际变色的中间帧、明确指定颜色的链接/code/del、恢复基础颜色和光标几何；原生与 fractional 后端均运行。相关回归 **8/8** 通过，包含文字后端、行内交互/生成内容及 literal 编辑几何。

完整 Release 构建通过，完整 CTest **339/339** 通过，耗时 **445.07 秒**；日志为 `build/hot-text-release-build.log`、`build/hot-text-all-ctest.log`。手动目标构建日志为 `build/hot-text-final-probe-build.log`。为配合用户保留测量窗口前台，先前启动的一次完整测试已中止，最终测试在全部 GUI 测量结束后从头运行，没有和正式测量并发。

汇总工具校验六组窗口状态、阶段、样本与绘制覆盖；独立重算 1080 个同步/投递/排队/绘制分位数，与输出一致，并核对环境/节奏、80 次热绘制、零静态颜色覆盖与隐藏绘制/已记录 Timer 事件。诊断校验日志为 `build/hot-text-validation.log`。Python/PowerShell 语法、手动基准 C++ 格式和 `git diff --check` 检查通过；没有放宽已有性能或像素断言。

`dist` 已刷新，Muffin.exe、MuffinCore.dll、MuffinUi.dll 的 SHA-256 均与 Release 一致，打包日志为 `build/hot-text-dist.log`。可运行程序为 `build/dist/Muffin.exe`。

## 复现

```powershell
cmake --build --preset conan-release
cmake --build --preset conan-release --target MuffinGuiPerformanceProbe MuffinThemePerformanceProbe
$env:MUFFIN_GUI_PIN_WINDOW = '1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_gui_performance.ps1 -OutputDirectory build/hot-text-gui
python scripts/summarize_gui_performance.py build/hot-text-gui build/hot-text-gui/summary.json
ctest --preset conan-release --output-on-failure
cmake --build --preset conan-release --target dist
```

需要交互桌面，置顶只作用于临时基准窗口。运行期间不点击其他窗口，不并发构建/测试；失焦运行按原验收条件排除，可用 `-SizesMiB 30 -TabCounts 3` 单独补测。
