# 多标签页内存拆分与 AST 存储优化

日期：2026-10-16。完整记录、固定资源/二进制摘要和独立审计见 [JSON](tab-memory-2026-10-16.json)。本轮没有 commit 或 push。

## 结论与实现

这份富行内语法样例的主要占用来自 AST，而非隐藏页的详细布局。每个 30 MiB 文档约有 **486 万个行内节点**、2.93 万个块节点，但驻留详细布局只有 **12 个块**。因此本轮优先压缩节点，不增加隐藏页布局回收策略，也不改变现有光标、滚动、编辑及隐藏页资源延后更新机制。

`InlineNode` 的八个源码坐标通常使用 32 位存储。公开接口和运算保持 `qsizetype`；任意坐标超出 32 位范围时，整个坐标组转入已有可选元数据中的完整宽度存储，回到常规范围后释放。没有截断、饱和或缩小可编辑文件范围。常见 Markdown 标记使用对齐空隙内的一个字节编码，共享不可变字符串；自定义标记、链接、图片及自动链接信息仍按需分配。普通节点由 **136 字节降至 104 字节**。

新增回归覆盖宽度边界及随机全宽坐标、深复制/赋值独立性、嵌套源码位置移动跨越边界，以及常见/自定义/空标记切换时其他元数据的保留。既有解析、投影、增量编辑、字体和显示回归继续通过。

## 测量方法与边界

使用真实 Windows QPA `MainWindow`，Qt 6.11.1，1100×820，DPR 1、96 DPI，三主题为 VLOOK Fancy Dark、GitHub、Phycat Abyss，初始 Night。每份正式进程执行六轮主题操作、输入、隐藏页激活及重复切页；保留实际 Windows 前台、Qt 激活/可见和整视口 Paint 校验。输入使用 Qt 投递，Paint 是 QWidget 派发完成，不代表物理键盘或 DWM 显示延迟。

六组 **1/10/30 MiB × 单页/三页**，修改前每组一个新进程，修改后每组两个；前后分别另有两个关闭诊断对照及一个启动样例。前后顺序测量，没有交错二进制。计时期间没有并行构建、测试或外部统计进程。所有样本保留，少量切页操作不能作为总体 p99 或长期泄漏证明。

新增 `--memory-census` 仅对手动 GUI 工具启用。打开每页、各交互阶段末、草稿排空、逐页关闭及关闭后 1/5 秒记录工作集和私有提交；计数草稿队列、字体注册、图片/阴影缓存。复杂的对象容量清点放在计时、草稿排空的工作集检查之后。关闭通过标准标签页绑定执行，并用 `QPointer` 检查原文档对象销毁，最后保留一个空白页；不调用堆压缩或工作集裁剪。

首次基线编排曾过滤掉可选 census 环境变量，六组的计时和工作集仍有效，但**没有对象清点或关闭检查**。修正为显式参数后，在改产品前另测一个有效的 30 MiB 三页清点样例；修改后十二份正式记录均有清点和关闭检查。该单独基线与六组正式数据分开保留。

容量清点按唯一 Qt 缓冲去重并统计原生对象/vector 容量。它不包含分配器头部、QHash 完整结构、Qt 文字整形、操作系统字体及全部其他缓存，不能与进程工作集直接求和。位置 token 为独立估算项；详细布局只记录基本对象下限及样式条目数量。CSS 图片数字只覆盖当前源码样式表的资源缓存，**没有涵盖全部编译后缓存**；16 MiB SVG 数字是每缓存预算，不是实际驻留。

## 文本、AST 与布局

30 MiB 清点样例每页的容量，单位 MiB：

| 来源 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 文本缓冲（共享原文去重） | 60.000 | 60.000 |
| 文本索引/vector | 32.500 | 32.500 |
| AST 块对象 | 5.140 | 5.140 |
| AST 行内数组等容量 | 630.541 | 482.252 |
| AST 可选元数据 | 136.867 | 36.849 |
| AST 字符串容量 | 13.160 | 13.160 |
| 上述可计数容量小计 | **878.210** | **629.903** |

每页减少 **248.307 MiB**，三页约 745 MiB；工作集还受分配器粒度和驻留状态影响。节点数量、共享文本数量及字符串容量均一致。另列文档位置 token 估算约 **4.021 MiB**，不计入上述小计。

前后布局均为 29,279 个槽、12 个驻留详细块：槽容量 **2.234 MiB**，布局位置 token **1.564 MiB**，详细块对象下限 **0.120 MiB**，块/行内样式缓存条目 **94/323**。未公开的整形内存没有计入，但现有可测证据不支持用隐藏页回收策略替代 AST 优化。

排空后，本样例的盒阴影缓存约 **5.79 MiB**、文字阴影约 **0.125 MiB**，文档图片缓存为 0；当前源码 CSS 资源缓存计数不能推断所有 CSS 图片占用为零。累计注册 **10 个私有字体面、向 Qt 提交约 41.35 MiB 字体数据**；这是累计提交量，不能当作操作系统字体实际驻留量，也不能与阴影和工作集重复相加。

## 草稿临时内存与关闭页

另用修改后的诊断工具补测一个有效 30 MiB 三页进程，四轮主题操作。保留写入请求前后及每次已有 50ms 排空轮询的队列/进程采样，共 12 条；可能漏掉更短的峰值。此时有两个已编辑页，最多一个正在写入、一个待写，分别约 31,457,456 个逻辑 UTF-16 code unit。快照共享原始文本及 Qt 索引，这个逻辑长度不能当作快照独占内存。

| 检查点 | 工作集 MiB | 私有提交 MiB |
| --- | ---: | ---: |
| 请求写入前 | 2630.023 | 2593.168 |
| 采样最大值 | 2720.121 | 2743.500 |
| 两个草稿排空 | 2630.055 | 2593.199 |

采样增量约 **90.10/150.33 MiB**，排空后仅比写入前高约 **0.03 MiB**。文本展平、UTF-8 编码及写入产生临时缓冲；本轮没有观察到队列排空后持续累积，不引入新的草稿缓存机制。该单次排空等待约 **252.69ms**，不是 I/O 延迟分布或前后提速结论。

主矩阵旧版 census 的 `draft_drain.wait_ms` 把清点开销也算进去，**不能用于比较草稿 I/O 时长**；排空前的交互计时和排空工作集不受影响。补测版已将等待结束时间移到清点之前。旧矩阵工具二进制保存在 `build/tab-memory-matrix-bin/`，补测工具单独记录摘要，产品 exe/Core/Ui 及资源保持一致。

修改后十二份正式记录的全部原文档对象均销毁，草稿 pending/running 均归零。30 MiB 三页关闭后 5 秒，两个进程工作集为 **355.57/355.94 MiB**，私有提交约 **255.19/255.27 MiB**。单独修改前清点样例约 **315.08 MiB**，不能声称关闭后的常驻内存也下降；字体、全局绘制缓存和分配器保留页仍存在。有限轮次没有发现文档对象残留，不等于证明不存在所有长期泄漏。

30 MiB 三页单独修改前样例的逐页关闭处理为 **2475/2482/1469ms**；修改后两份分别为 **706/513/457ms**、**489/476/452ms**。该改进与减少大量节点/元数据释放相符，但基线只有一份，仍保留几百毫秒的关闭成本。
