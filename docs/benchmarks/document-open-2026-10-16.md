# 大文档打开链路拆分与后台准备

日期：2026-10-16。完整数据、全部样本、资源/二进制摘要及独立审计见 [JSON](document-open-2026-10-16.json)。本轮未 commit、未 push。

## 结果

现有打开路径本来已使用后台解析，主要界面阻塞发生在解析结束后的安装：文本索引、共享文本绑定、坐标转换和未完成语法标记扫描仍在 GUI 线程执行。现在由同一个后台任务准备尚未发布的数据，再由 GUI 线程检查并安装。

30 MiB 单页 GUI 安装中位数 **1200.56→270.93ms**，三页场景每次打开的中位数 **1231.21→234.43ms**，减少约 **77%–81%**。这些是该阶段占用 GUI 线程的时长，不是完整打开时间。

总打开至首屏仅小幅改善：30 MiB 单页 **6202.86→5976.38ms**，三页每次打开 **6335.34→6030.93ms**。10 MiB 三页出现反向波动；内存峰值基本不变。后台仍有 cmark 解析、AST 转换及删除线处理的数秒工作，不能将 GUI 安装缩短解释为打开等待已经解决。

## 测量口径

真实 Windows QPA `MainWindow`，Qt 6.11.1，1100×820、DPR 1、96 DPI。沿用 **1/10/30 MiB × 单页/三页**，修改前每组一个新进程，修改后每组两个，各另有两个关闭诊断对照和一个启动样例；三主题为 VLOOK Fancy Dark、GitHub、Phycat Abyss，初始 Night。每进程四轮主题操作，随后输入、切页、草稿排空、视觉/编号参考和标准关闭。

打开时新增独立 `muffin.perf.open` 粗粒度类别，不启动已有逐行内节点计时。记录同步打开入口返回、后台解析各阶段、GUI 安装结束和新文档首次完整视口 Paint。另记录每阶段工作集、20ms 采样峰值及进程历史峰值。关闭诊断对照禁用打开阶段计时。计时中没有并行构建、CTest 或图像统计。

全部正式与对照取得实际 Windows 前台、Qt 激活/可见，首屏也独立检查。完成 QWidget Paint 不代表 DWM 展示延迟；交互使用 Qt 投递，不恢复暂缓的原生键盘调查。文件在计时前即时生成，因此读取使用温热的系统文件缓存，**不代表冷磁盘或网络文件性能**。

前后顺序测量，没有交错二进制；每格只有修改前一进程、修改后两进程，三页数据包含同进程首次与后续打开，不能作为总体 p95/p99。首个文件独立样本、每次原始时间均保留。创建后续标签页时还会同步解析空白启动文档，粗粒度日志完整保留；统计解析成本时仅选择真正的后台文件解析，文本索引也排除空白页准备，避免混淆。

首屏阶段统计为打开请求至完成检测期间的累计独占 CSS/计数器/布局/绘制工作，包含加载状态等界面更新；不是每个节点或单次 Paint 的精确分摊。它与包含子调用的发布/安装 scope 不能相加。

## 热点与实现

### 将未发布数据的准备放入现有后台任务

`DocumentSession::AsyncParseResult` 持有解析 AST、准备好的 `PieceTable` 和未完成标记偏移。后台顺序完成语法修正、绑定共享原文、转换块相对坐标、收集标记和建立文本索引；这些数据没有 QObject 线程归属，不读写活动文档或视图。

GUI 线程继续检查结果有效性，并经 `MarkdownDocument::setPreparedMarkdownText()` 移入文本索引和 AST，绑定行号索引、创建源码位置 token/节点索引/大纲，然后发出原有更新信号。原文 QString 和索引使用共享/移动，没有再次扫描文本建立同一份 `PieceTable`，也没有新增缓存预算或第二套解析路径。现有同步编辑路径仍同步执行。

发布前保持加载状态；只有安装完成后才能编辑。加载中修改解析选项、再次打开和已有过期结果检查继续沿用公共路径，worker 不捕获 `DocumentSession` 指针。新增同步/异步 AST、全部行内源码坐标、共享文本、行号查询、未完成标记及安装后局部编辑对照；`documentReset` 的观察者看到完整准备后的节点。

### 减少通用行内分隔符处理的复制

删除线、上下标和高亮共用的后处理会为整个行内列表构造 token，并深复制格式化节点；即使没有匹配，最终也会创建临时列表后丢弃。现在先检查当前列表中可分割的源码对齐 Text 候选，无候选直接返回。匹配期间借用未改变的原节点；确认一对分隔符后才转移其内容，最终列表按移动提交，没有匹配则完整保留输入。

没有改变分隔符配对、空白侧翼、转义、实体、源码范围或原有嵌套处理语义；marker-free Text 在已提交列表中的范围重建仍保持原规则。回归覆盖跨格式匹配、表格、链接目标、代码、实体与转义，以及其他段落出现标记时普通文本的坐标。

固定样例每个正文段落都含删除线，候选过滤本身不能跳过大部分列表。减少复制仍只有有限收益，不能声称已消除这一阶段。

采样内存峰值没有明显改善：30 MiB 单页约 **1238.7→1238.5–1240.4 MiB**；三页最后一次打开约 **2779.5→2773.4–2777.6 MiB**。峰值仍由 cmark 原生树及 AST 转换过程主导。20ms 采样会漏过短峰，进程 `peak_working_set_bytes` 为历史值，两者口径分开保留。

## 诊断与视觉补测

正式阶段记录没有开启逐行内节点计时，关闭诊断对照也没有打开 scope。另增加五个前台补测进程，使用相同更新版手动工具分别加载固定修改前/后产品 DLL，产品版本不变。

30 MiB 单页关闭打开诊断的单独样本为 **6620.20→6199.79ms**；同一修改前版本启用旧逐节点计时为 **6913.47ms**。这些顺序单样本不能精确归因出计时成本，但确认约 6 秒等待仍真实存在。1 MiB 三页关闭诊断的补测也有反向波动，不筛掉以换取统一收益。

主矩阵修改后 **45 对**重复像素/字体/几何/光标全部一致，独立解码 **105 张 PNG**；前后 **84 对**几何、字体和编辑坐标一致，**80/84** 像素完全一致。四对差异限定在 Phycat 正文链接的颜色、发光及旋转图标区域，裁剪图和 CSS `a:hover`/伪元素规则已检查，原图完整保留。

补测只在计时结束后的视觉参考前，通过编辑器正常 Qt `Leave` 事件清除指针交互状态，不移动系统鼠标、不禁用主题动画。1 MiB 三页及 30 MiB 单页的三主题前后 **12/12** 对像素/字体/几何/光标完全一致，另 **15/15** 对重复像素一致。因此主矩阵这四对差异来自未固定的 hover 动效状态，没有把它们改写为原始像素相同。人工查看裁剪图和最终 Phycat 截图，主题效果保留。

独立复算主矩阵 **1710 项统计、2772 个时钟差、48 条前后打开时间线**，全量计数器/生成内容指纹通过；隐藏页无绘制，切页后输入和草稿确认通过。
