# Windows GUI 主题切换续测结果（2026-10-16）

本次完成 **12/12 正式进程、2/2 关闭诊断对照**，另有一份有效启动样例。正式进程覆盖 **1/10/30 MiB × 单页/三页 × 两轮新进程**，每进程六轮 VLOOK Fancy Dark、GitHub、Phycat Abyss，共 **216 次主题操作**。全部记录保持实际 Windows 前台、Qt 激活、可见和编辑区就绪，隐藏页没有绘制，切页后输入、草稿排空及可见坐标检查通过。

**测量完成，但性能仍有明确缺口：Phycat 首次选择在三页模式为 1.37–2.02 秒，两个隐藏编辑器的排队回调仍执行了昂贵工作。** 这轮没有修改产品代码，没有宣称性能问题已修复。见[完整原始数据、分位数及独立审计](gui-theme-switch-completed-2026-10-16.json)。[此前桌面阻塞及失败记录](gui-theme-switch-2026-10-16.md)继续保留。

## 有效性与前台交接

用户恢复桌面后的三页预检取得有效前台，原来的 OpenInputDesktop error `5` 已不再出现。独立启动下一测量进程时，输入桌面可读、Qt active/exposed/focus 均为真，但 Win32 foreground 归 Explorer，因而该次记录被拒绝，没有执行计时操作。另一次启动样例在最后切页阶段短暂失活，同样保留并拒绝。

新增 `scripts/run_gui_theme_chain.py`：由仍在前台的基准进程启动下一个独立基准进程。下一个进程等待前驱真正退出，才加载文档并开始测量；没有两个文档基准并发计时。显式 `AllowSetForegroundWindow(nextPID)` 的十四次调用实际全部返回错误 `87`，逐次保留；没有据此认定前台成功。由前台进程启动的子进程通过普通 Qt 激活取得前台，仍在每阶段开始前和测量中验证实际 Win32 foreground、Qt active/exposed。全部十五个进程通过这些条件，不能把“请求激活”替代为“已在前台”。

运行中协调器只检查小型状态文件和所拥有进程的退出状态，不启动额外 PowerShell 日志读取进程，不并行构建、测试、摘要计算或图像分析。统计和文件摘要在全部 GUI 进程退出后进行。没有修改系统设置、连接其他进程的输入队列、伪造前台状态或绕过安全桌面。computer-use 服务仍因 kernel assets 路径缺失无法初始化，实际测量使用项目自身 GUI 进程。

环境：Windows QPA、Qt **6.11.1**、窗口 **1100×820**、DPR **1**、逻辑 DPI **96**；单页视口 **1086×761**，三页 **1086×723**。Qt 报告屏幕刷新率 **32Hz**，不将其解释为物理显示器刷新率。

## 已定位的隐藏页资源刷新路径

Phycat 三页首次选择，主题处理本身约 **474.5–568.9ms**；处理结束到首屏 Paint 开始又等待 **820.9–1389.1ms**。最小诊断观测到两个隐藏 EditorView 的 `QEvent::MetaCall`（类型 43）各执行一次，整段主题阶段合计时间如下：

| 文档/轮次 | 处理结束到 Paint 开始（ms） | 两个隐藏 MetaCall 合计（ms） |
| --- | --- | --- |
| 1 MiB / 1 | 856.095 | 855.231 |
| 1 MiB / 2 | 820.912 | 820.235 |
| 10 MiB / 1 | 870.225 | 869.278 |
| 10 MiB / 2 | 905.041 | 891.733 |
| 30 MiB / 1 | 1174.126 | 1173.034 |
| 30 MiB / 2 | 1389.147 | 1388.103 |

隐藏 MetaCall 的统计是整个 theme_switch 阶段的总量，不是带调用栈的逐事件归因；本轮不声称已捕获单个回调的完整栈。但六份记录与源码路径给出一致、可操作的证据：

1. `LayoutResources` 监听 `QGuiApplication::fontDatabaseChanged`，发布全局字体资源 revision。
2. 每个 EditorView 收到 `resourceChanged` 后调用 `queueResourceRefresh()`，用 `QTimer::singleShot(0, this, ...)` 排队。
3. 回调检查文档、加载和布局状态，**没有检查视图可见性**；因此隐藏标签页也调用 `DocumentLayout::refreshResources()`。
4. 字体 revision 变化允许样式失效，资源刷新可能重新建立布局及行内 CSS；`pendingTheme` 只延后主题应用，未阻止这条资源刷新路径。

因此下一轮应首先让**隐藏视图的资源刷新延后到激活时**，并在应用 pendingTheme 后合并消费资源失效，避免先按旧主题重建一次再按新主题重建。字体身份/回退和资源 revision 必须保留；不能直接忽略字体数据库通知。回归应覆盖隐藏页首次注册字体、激活后的换行/坐标、异步图片/字体更新、加载取消、主题与资源更新交错及关闭页安全。

重复主题操作时，三主题的主要独占阶段仍为 CSS 和布局；例如 30 MiB 三页 VLOOK 的重复操作 p50：布局 **104.2ms**、CSS **46.3ms**、计数器 **34.0ms**。这些是各阶段独立取 p50，不能相加得到某条完整样本。此固定首屏中的背景/阴影已不是约一秒停顿的主要来源，不外推为所有页面内容都没有效果绘制成本。

包含启动样例在内，三主题两轮形成 **45 对**重复可见块/行内几何、字体、颜色及光标回查，全部一致；解码检查 **105 张 PNG**。VLOOK/GitHub 的 **30 对**像素完全一致，Phycat **14/15 对**完全一致；另一对相差 **13644 像素**，差异图集中在背景点阵亮度，块几何、字体、正文颜色和坐标仍一致。保留该差异，不宣称全部主题像素相同；主题动画没有关闭，当前观测未独立证明点阵差异的全部原因。人工查看最大文档三页的最终 Phycat/VLOOK 及单页 GitHub，标题、正文、行内元素和嵌套列表可见，无主题颜色串用。此检查验证切换失效，不能替代此前浏览器/Typora 全量兼容回归。
