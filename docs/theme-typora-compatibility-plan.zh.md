# Typora/VLOOK 主题兼容计划

这份计划记录 Muffin 对 Typora/VLOOK 风格主题的兼容目标、实施顺序和验证方式。目标是让主题依赖稳定的 Markdown 语义结构和明确的 CSS 能力矩阵，而不是为某一个主题加入临时选择器特判。

## 当前差异和根因

- VLOOK 大量使用 `content>#write`，而编辑器样式树此前只有 `html > body > #write`，导致页面盒子、背景和标题规则无法命中。
- Markdown 节点没有完整映射 Typora 常用的语义类和属性，例如 `md-inline`、`md-task-list-item`、`md-alert-*`、代码语言和任务复选框属性。
- CSS 解析器会跳过 `@supports`，所以由能力查询包裹的滤镜和部分装饰规则会消失。Fancy Dark 的网格是 `content>#write` 的内嵌 PNG 背景，另外受到普通页面 `background-image` 未绘制的影响，与 `@supports` 是两个独立问题。
- 主题切换会同步重建每个打开文档的布局，大型文档的耗时来自全量布局，不只是 CSS 文件解析。
- VLOOK 的远程字体不能在渲染时依赖网络，字体回退会改变字宽、行高和换行位置。
- 真实快照还暴露出 CSS 变量替换的 token 拼接错误：`var(--weight)1em` 被读成 `5001em`，异常放大的字体同时影响正文与布局性能；本次修复 token 边界。多层 `background` 简写中的逗号也需要在级联中保留，不能把内嵌图片和末层底色当成同一个 token。

## 实施阶段

### 第一阶段：语义兼容层（已完成首轮）

1. 将公共宿主结构固定为 `html > body > content > #write`。
2. Markdown AST 到 CSS 元素的映射集中在 `NodeCssElementBuilder`，覆盖标题、列表、任务列表、告警引用、代码块、表格、链接和行内标记。
3. 任务项提供 `md-task-list-item`、`task-list`、`input[type=checkbox]` 和 `checked` 等稳定语义信息。
4. 告警引用提供 `md-alert` 和 `md-alert-{note,tip,important,warning,caution}` 类。
   行内元素采用 `span[md-inline=strong/em/code/link/strike/highlight/sub/sup/math]` 包裹对应原生语义标签；样式原型与真实 AST 使用同一拓扑。代码块提供 `md-fences`、`md-fencescode`、语言类和属性；数学块提供 `md-math-block`、`mathjax-block`。
5. 保留 CSS 原有选择器和级联顺序，主题不需要知道内部 MarkdownNode 类型。

### 第二阶段：条件规则和兼容诊断（条件解析与离线诊断首轮已完成）

1. 解析嵌套 `@supports`，支持 `and`、`or`、`not` 和声明能力查询。
2. 能力判断以 Muffin 实际可绘制的属性为准；暂不支持的能力不会误应用。
3. 将条件保存在 `CssRule` 中，并在环境切换时重新评估，避免把条件规则静默丢弃。
4. 已增加按需运行的离线主题兼容性报告，统计未支持的 at-rule、选择器、属性值和资源，并将字体存在性与实际注册结果分开。

能力查询遵循 [CSS Conditional Rules](https://www.w3.org/TR/css-conditional-3/#at-supports)：同层不混用 `and/or`；语法无效的条件不能经 `not` 反转成有效规则。当前共享级联的颜色、长度、grid/flex 等值校验，并验证实际绘制支持的滤镜参数；未知属性、查询函数、`display:contents`、`counter-set` 保守返回不支持。未命中的分支不能污染根变量或注册动画/字体。相同查询在一次样式表评估中只计算一次。

### 第三阶段：VLOOK Fancy Dark 回归样例

固定原始 VLOOK V2026.10.1 Fancy Dark CSS 快照及一个小型 Markdown 样例，保留许可证、来源和 SHA-256，离线覆盖真实选择器和最重要的视觉结果：

- `content>#write` 页面背景和内嵌 PNG 网格（第一层图片）；
- `@supports (backdrop-filter: ...)` 分支；
- 标题横条和伪元素；
- 正文、链接、行内代码、键盘标签；
- 列表、任务复选框、表格和代码块。

测试分层断言 AST 语义、DOM 命中、计算样式、布局和像素结果；生成固定 960×900 视口截图用于人工检查，不使用依赖平台字体的整图逐像素比较。

### 第四阶段：高价值绘制能力（背景、属性内容、表格和告警首轮已完成）

优先完善完整多层页面背景、通用 `attr()` 生成内容、表格容器和告警结构；随后核对计数器、遮罩、滤镜及有限定位布局的边界行为。复用已有 repeating/radial gradient、元素交互状态和属性动画，以及 `LayoutBox`、`CssDecorationExtractor`、`InlineLayout` 和 `BlockLayout`。

### 第五阶段：字体和性能（字体见第七轮，阴影与性能测量见第八轮）

- 提供可选的本地主题字体包；没有字体时使用固定的字体映射和确定性回退。
- CSS 解析、变量计算和选择器编译生成不可变 `ThemeSnapshot` 并缓存。
- 当前标签页立即更新可视区域，隐藏标签页延迟到激活时重建。
- 字体、图片和图表资源变化在隐藏视图中只保留失效标记，激活时结合最新主题与文档合并更新；返回渲染模式及首次绘制前保证资源依赖和坐标正确（第三十轮已完成）。
- 连续切换主题时合并 generation，丢弃过期布局任务；Qt 布局和绘制对象仍只在 GUI 线程创建。

## 验证门槛

每个阶段都使用同一个 VLOOK Fancy Dark 样例和固定视口验证。Release 构建后运行完整 CTest；新增兼容能力必须有单元测试，且现有内置主题的 `body/#write` 级联和 HTML 渲染测试保持通过。

## 首轮交付范围

本次先完成第一阶段的 `content` 宿主节点、Markdown 语义类映射和第二阶段的 `@supports` 解析，并加入第三阶段的固定回归样例。主题应用的隐藏标签页延迟和字体包属于后续独立变更，避免把布局性能改动和 CSS 兼容改动混在一起。

为了让网格回归覆盖实际显示，首轮同时让页面复用 `LayoutBox` 背景绘制，支持第一层内嵌 base64 位图、自然尺寸、定位、重复和显式尺寸，解码缓存最多保留 32 个数据 URL，以 URL 内容为键，CSS 图片更新会自动产生新键。首轮登记的多层背景、`cover/contain` 和表格 `figure.table-figure` 容器已在第二轮补齐。外部 URL 资源、复杂 `:has()`、字体注册/回退及 VLOOK 脚本生成组件仍是后续验收项，不能据此宣称与 Typora 完全一致。

## 第三轮：按需兼容诊断

新增公共 `CssCompatibilityReport` API 和开发工具 `muffin-theme-report`，复用解析器、选择器编译器、条件求值及声明能力校验。报告不会在启动或列举主题时执行；不启动 GUI，不注册字体，不访问远程资源。

```powershell
cmake --build --preset conan-release --target muffin-theme-report
.\build\Release\muffin-theme-report.exe --dark --width 960 --height 900 `
  --output build\vlook-compatibility.json `
  tests\fixtures\theme\vlook-fancy-dark\vlook-fancy-dark.css
```

报告保留原始文件及导入文件的规则行列位置，列出资源缺失/未加载、跳过的 at-rule、不支持的选择器、背景平铺/混合模式、部分定位和生成内容限制。重复问题合并计数，每组最多保留三个例子；长数据 URL 截断并附内容 SHA-256，避免报告被内嵌图片撑大。

`active-rule`、`inactive-condition`、`blocked-selector`、`excluded-context` 分别表示条件生效、条件未生效、选择器不可用、Typora 编辑器/导出专用结构。条件生效不等于规则命中文档或赢得级联，报告不能据此计算视觉兼容百分比。

报告明确区分“已知不支持”“尚无完整校验”和“需要元素上下文”：`font-family`、`box-shadow` 等已有绘制路径但未纳入完整能力校验的属性不会被误报为不支持；`var()` 不按全局变量表猜测结果。字体报告仅检查资源路径，不宣称字体解码、注册或回退已通过。完整 CSS 语法校验、关键帧属性审计和最终文档几何/像素仍需对应回归。

新增 `MuffinCssCompatibilityReportTest`，验证导入与嵌套规则来源、条件隔离、选择器排除、属性误报边界、资源解析及输出上限，并通过实际 CLI 生成固定 VLOOK 报告 `build/Release/vlook-fancy-dark-compatibility.json`。下一项继续资源加载与背景平铺/混合模式的公共能力。

固定快照在 dark、960×900 环境下含 2,258 条规则，其中 2,194 条通过条件、64 条未通过；436 个选择器属于明确排除的 Typora 编辑器/导出结构。报告识别出 3 个未加载的远程字体样式导入、204 个编译器无法评估的选择器，以及 `display:contents`、`filter:drop-shadow(...)`、固定/粘性定位等能力差距。选择器统计包括 VLOOK 自身组件和 Typora UI，并不表示这些规则都会影响当前 Markdown。变量依赖和未完成校验项单独记录，不能将这些数量解释为视觉错误数量或兼容率。

本轮验证：Release 构建通过，完整 CTest **332/332** 通过，`dist` 已刷新；`git diff --check` 无错误。

## 第四轮：公共图片资源、背景平铺和混合模式

本轮继续通用 CSS 能力，不按 VLOOK/phycat 主题名称特判。

| 能力 | 实现和回归 |
| --- | --- |
| 图片资源 | 支持本地、`file:`、Qt 资源及内嵌位图/SVG；声明保留所属目录，导入 CSS 和变量中的相对路径按定义位置解析；URL 转义、百分号编码和括号与依赖扫描共用规则 |
| 资源缓存 | 缓存跟随主题快照：解码源 32 MiB/最多 64 项，SVG 派生位图在同一快照内共享 16 MiB；重新加载创建新缓存，沿用 SHA-256 依赖清单使同大小/同时间戳更新及新建资源失效；不存磁盘 |
| SVG | 按目标尺寸/DPR 光栅化；支持固有尺寸、仅有 viewBox 时的默认尺寸、`preserveAspectRatio` 的对齐/meet/slice/none；关闭 SVG 自身动画 |
| `space` | 在定位区域两端分配完整图片并均匀留白；不足两张时按 background-position 放置单张；两个轴独立处理 |
| `round` | 按最近整数确定张数并调整尺寸，按规则缩放另一条 auto 轴；保留 Chromium 使用的调整前百分比定位锚点 |
| 背景混合 | 覆盖 normal、multiply、screen、overlay、darken、lighten、color-dodge、color-burn、hard-light、soft-light、difference、exclusion、hue、saturation、color、luminosity；背景组与祖先、边框和文字隔离 |
| 公共绘制路径 | 页面、块、行内和伪元素背景使用同一绘制器；普通背景继续直接绘制，混合背景只为可见交集分配临时图层；SVG 背景不再同时作为 content 图标重复绘制 |
| 条件和诊断 | `@supports` 能识别新增能力，非法 repeat/blend 声明保留前一个有效声明；诊断报告删除已补齐的限制，远程资源和 `mix-blend-mode` 继续明确记录 |

## 第五轮：告警标题 SVG 与通用行内生成内容

此前行内 `::before/::after` 只会为链接生成布局原子，告警标题的兼容节点和其他 Markdown 语义元素虽能匹配 CSS，却不会插入生成内容。VLOOK 本身还依赖 Typora 提供 `.md-alert-text svg`，仅解析主题中的伪元素无法补出该图标。

| 能力 | 实现和回归 |
| --- | --- |
| 通用行内伪元素 | Markdown 语义元素及 `md-inline` 祖先包装层共用生成内容布局；告警标题、加粗、斜体和链接可以同时生成文字、背景或 SVG 遮罩原子；按语义树顺序处理嵌套前后缀和相邻边界 |

## 第七轮：字体基线与通用字体映射

### Mermaid 基线根因

Windows 安装的 Noto Sans Bold 与应用固定的 Noto Sans Regular 同名。Qt 在请求粗体时选中了系统 Bold，浏览器参考则只加载固定 Regular 文件并合成粗体，二者的 advance 不同。采用私有字体族隔离固定资源后，原有 `MuffinMermaidThemeCssTest` 通过，未改变参考数据和容差。

私有身份由字体内容决定，只修改内存中的 SFNT 名称及匹配元数据，原始字体文件不变。静态字体导出中残留的 STAT 实例枚举不参与私有静态字形匹配；轮廓、advance、字距和整形表保持原样。Mermaid 和文档回退共用同一套固定 Noto 资源及注册结果。

图表的全局标题、ex/ch 相对长度、测量和绘制统一解析私有字体映射；首选字体缺失时，度量分支依据实际选中的字体，保留后续逐字形回退。Qt minimal 等不支持应用字体注册的平台继续使用原生回退。旧测试的字体身份检查验证实际映射；MathML 语义快照将私有名称还原为逻辑字体名比较，原有参考图、几何数据、金标准哈希和容差不变。

## 第八轮：超远阴影稀疏合成与大型文档测量

### 稀疏效果路径

VLOOK 使用 `drop-shadow(12345px 0 ...)` 将远处的图形着色后移回视口。旧实现用源图和阴影的整体包围盒分配中间图片，透明空隙也占用像素预算，因而触发降采样。这一轮改为从视口反推有序滤镜需要的源区域，用不相交的区域和 512 个物理像素的分片合成；模糊采样带保留邻片信息，最终输出仍使用原始 DPR。滤镜、遮罩、组透明度的顺序不变，块、行内元素、生成内容和 HTML 继续共用公共绘制入口。

偏移距离不再决定图片尺寸，单张带模糊采样带的表面小于 17 MiB。此上限不等于整个进程或多层滤镜的总内存上限；现有大模糊的三次 box blur 近似与半径限制保持不变。页面 `box-shadow` 分配也纳入隐式设备裁剪，避免为百万像素高的页面创建整页阴影图片。

固定浏览器效果样例增加正负远距离平移、模糊、滤镜链和遮罩组合，共 28 类 × DPR 1/1.25/2，即 84 组像素样例。原生回归另比较 12,345 与 1,000,001 像素偏移：相同亚像素相位下像素和分配量完全相同；跨越 512 像素边界的有序模糊链与原有整图计算逐像素一致。高页面阴影覆盖顶部和滚动后视口。

另补真实 QWidget 绘制回归：窗口尺寸为逻辑像素，QImage/QPixmap 尺寸为物理像素，公共设备裁剪先统一单位再反变换。`QT_SCALE_FACTOR=1.25` 下原路径会裁掉窗口右侧/底部效果，修复后通过；该配置独立注册为 `MuffinHighDpiCssEffectsCompatibilityTest`。

### 测量中修复的公共开销

- 计数器候选来自实际生效、受支持的编译后选择器，保留必要的宿主类与祖先类条件。VLOOK 导航面板的计数器不再让每个正文链接参与求值；普通 Markdown 先在 AST 上排除无关行内树，只对候选及祖先计算样式。任意类名、局部变量和计数器的行内 HTML 保留完整匹配路径。
- `:has(tag/class)` 的否定查询直接检查 Markdown AST，不为不存在的图片或类创建整棵行内 CSS 树；结果随语义树快照缓存，文档样式失效后一起丢弃。语义子节点去重改用集合，避免大量兄弟块的线性重复查找。
- CSS 指纹复用隐式共享变量表的哈希，避免为每种行内状态反复散列 VLOOK 内嵌资源。缓存仅在进程线程内保留四个共享快照；变量修改触发写时复制，使旧身份失效，不写磁盘缓存。回归验证新旧样式快照与修改后的哈希。
- 隐藏标签页只保存最后一次主题快照，激活时再应用；连续切换会合并。集成回归检查隐藏布局未换主题、激活采用最新主题、文档版本和光标身份保持。

## 第九轮：CSS 交互状态计算

### 公共计算路径

上一轮首屏 CSS 开销主要来自状态配方：带有 `subject` 的查询绕过样式缓存，每个元素的八种状态又反复匹配静态选择器并重算祖先。只按标签筛选交互候选，也让许多实际不匹配主题界面类的正文元素进入该路径。

- 不可变语义元素按生命周期身份缓存结构匹配：静态选择器的结果只计算一次，动态规则先检查标签、类、属性、祖先和结构条件。实际状态求值只遍历剩余候选，保留每条规则的最高匹配 specificity 及原始顺序。
- `:is()`、`:where()`、`:not()` 递归保留状态依赖。结构预筛时不使用动态否定条件排除候选，避免将 `:not(:hover)` 错当成永远不匹配。
- scoped 样式按实际匹配规则和继承值复用，哈希后比较完整输入。缓存不保存临时交互 `subject` 的地址；切换到另一个子元素时，可以共享相同的祖先状态结果。没有相关状态依赖时直接复用普通样式快照。
- 状态配方按实际 hover/focus/active 依赖编译组合，其余运行时状态复用已有的投影、transition 和 keyframe 轨道。依然提供完整八种运行时状态，绘制阶段只采样这些值；伪元素使用独立且稳定的快照身份。
- scoped 选择器的所有 compound 使用同一个真实状态主体，补齐 `p:hover > strong` 及 `strong:hover + strong` 的匹配；焦点限定在主体，hover/active 沿祖先传播，不传给无关兄弟。祖先继承依赖纳入状态候选，避免丢失颜色和自定义变量的变化。

缓存限于进程中的引擎/文档快照。文档样式失效会清除结果，主题或生效媒体规则变化采用隔离的新快照；临时元素及调用方声明继续绕过 computed identity 缓存。继承依赖目前采用保守并集，尚未按具体继承属性进一步裁剪。

## 第十轮：计数器增量更新、绘制与原型快照

### 候选发现和作用域传播

计数器发现先按编译后的选择器检查块标签、语义类、祖先类条件和可能的行内类型。普通 Markdown 无法生成任意作者类和 ID；行内 HTML 可以引入属性、类和局部声明，因此保留其完整语义路径。非候选段落不参与 CSS 求值，必要祖先仍参与计算，保留继承变量和 `display:none` 的影响。

计数器的 reset/increment/set 操作、生成内容 token 和稳定语义键编译为独立程序，不保存 AST 或 CSS 适配器地址。生成内容按块身份及局部语义路径定位，前面的文本长度变化不再使后面所有计数器缓存失效。

局部编辑使用精确的顶层替换范围，只重新发现和编译替换块。每个编号块保存完整输入/输出状态以及生成结果：在文档顺序中传播变化，未变化程序的输入恢复一致后复用结果；嵌套实例保持父作用域共享与兄弟作用域语义。语义输入保留 HTML、属性、行内类型、块元数据和拓扑，排除普通文字与会移动的源码偏移，以完整序列化值比较，避免哈希碰撞被误认成相同上下文。

未知修改和主题/媒体变化采用全量重建。结构变化若可能影响 counter、自定义变量、content 或 display 的上下文选择器，则重新发现候选并比较实际匹配的声明、specificity 与祖先依赖；输入相同的程序继续复用，输入不同才重新求值和编译。界面规则必须满足语义目标和祖先条件才会引入上下文失效。普通文字编辑直接保留未变化块。保留的主题副本在更新计数器时分离缓存。

另修复公共兄弟匹配开销：主题封面规则可能包含 `h6 ~ h1`，即使文档没有 `h6`，旧路径也为每个 h1 扫描全部前序兄弟。现在先使用缓存的父元素子标签查询；缺少该标签时直接结束这条候选搜索，仍有标签时保留完整选择器匹配。

回归覆盖正文编辑零重新编译、未变化编号块零重新执行、标题插删和级别变化、嵌套列表、局部 `counter-set` 与 HTML 类变化、结构位置和祖先 `:has()` 变量依赖、主题副本。增量块/行内生成内容与同一文档的新全量计算比较；既有固定浏览器作用域样例保持不变。

### 绘制和原型快照

诊断新增背景、阴影、文字的独占时间。首轮 1 MiB 已有视口约 82 毫秒，其中阴影重复栅格化约 74 毫秒，背景约 2 毫秒、文字约 4 毫秒。公共 box-shadow 路径按精确的裁剪后几何、亚像素相位、颜色、圆角和模糊半径复用栅格，整数平移可以复用；缓存每线程最多保留 16 MiB，样式或裁剪变化使用新的键。远处不可见边界在保留圆角保护带后归一化，避免懒排版改变页面底部时让相同视口阴影失效。回归比较冷/暖路径与平移后的逐像素结果，并检查颜色、圆角、裁剪及两种超高页面的行为。

## 第十一轮：普通编辑的局部样式失效与快照内存

### 保留语义未变的样式与交互配方

普通文字编辑的主要开销来自样式失效：原路径清空整份文档的计算样式、行内交互配方、字体投影和稀疏 CSS 适配器，随后还遍历已排版块检查相关样式。即使计数器只更新几个节点，视口的行内状态也需要重新编译。

现在将精确顶层替换范围与完整 CSS 语义签名共同用于失效判断。签名包含块元数据、行内类型和拓扑、HTML 标记/属性/局部声明、链接目标，以及会生成语义类的告警标题；排除普通文字和源码偏移。不含计数器的主题也建立同样的语义基线。仅在签名完全一致、文档版本连续、适配器和引擎独占时保留样式；结构、属性、变量依赖、未知修改和主题/媒体变化继续更新相关计算。

被编辑块的 CSS 视图按预先保存的顶层身份和子路径重新绑定到新 AST，不解引用已删除的节点。行内视图按遍历序号更新源码范围，保留 CSS 身份、计算样式和 hover/focus/active 配方；未变化的块保留既有排版、字体和祖先查询结果，跳过无效的相关样式检查。重建当前块的文字和几何仍会执行。主题副本共享适配器时改为分离重建，避免影响保留的快照。

全量布局对照还发现了已有的页面尾部高度问题：更新最后一块时使用旧的固定底边距，与 CSS 页边距和 padding 不一致。局部、范围和完整布局现共用页面尾部高度公式；固定回归样例中原先多出的 70 像素得到修正。

既有连续按键测试还暴露了同步光标刷新与结构更新的顺序问题：分隔线后按 Enter，新 AST 已插入块，布局的范围替换仍在队列中；原先单块请求先清空样式、计算全篇计数器，最后才发现块数或身份不匹配而退出。现在先验证布局是否能接受请求，无效请求保留旧快照，由随后的范围更新负责结构依赖。新增固定回归检查该阶段不会遍历计数器或清空样式。既有 2 MiB 嵌套文档按键回归中，该次 Enter 的同步耗时由约 1,447 毫秒降至 6 毫秒；这是默认主题下的 offscreen 集成测试，与下方 VLOOK 样例分开记录。

### 压缩签名和计数器状态

普通段落常有相同的语义形状，旧路径为每块分别保存完整序列化签名。现在按完整字节值驻留共享，使用块引用计数；替换块后，最后一个引用消失的旧形状立即释放。输入/输出计数器状态改为不可变共享快照，哈希只选择候选桶，再比较全部名称、深度和值；状态池保留弱引用，计算时清理失效项，被替换的状态载荷随旧 memo 释放。

30 MiB 样例初始的 29,274 个块只有三种签名形状：若逐块存储，签名载荷约 70.6 MiB；共享后约 2.6 KiB。523 个编号块的输入/输出共用 524 个状态。以上仅统计签名载荷及活跃状态数量，不包含容器、分配器和 AST，也不能直接等同于进程内存。

新增回归在已有测试程序内执行，覆盖连续 40 次文字插入、行内偏移更新、样式和配方身份保留、未编辑块布局复用；另覆盖无计数器主题、嵌套列表、引用、表格、主题副本、加粗移除、HTML 类和链接目标修改、标题级别变化。结果与同一文档的新全量样式、排版和编号比较。内存回归检查两千个重复段落的共享状态，以及反复替换后旧签名不会累计。

## 第十三轮：冷区域选择器索引、分批预取与缓存驻留

### 从实际求值继续追踪命中路径

新块的相同 CSS 结果原先仍按元素身份分别保存，交互配方也分别投影。本轮先按完整匹配规则、继承值和根状态共享最终样式，并共享完整八状态输入一致的不可变配方。哈希只选择候选桶，完整输入必须相等；每个元素仍使用独立动画时间线。

第一次 GUI 对照中，冷滚动的 CSS 实际求值次数已降至零，但 CSS 路径仍约 10 秒。可单独开启的 `muffin.perf.css` 计时发现：一组 80 次冷滚动中，选择器首次筛选累计约 8.98 秒，匹配规则查询约 9.11 秒（包含筛选），指纹约 225 ms，最终结果查找约 274 ms（包含其内部指纹）；这些嵌套计时不能相加。只观察求值次数会漏掉主要开销。

### 按语义目标预编译候选组

原索引只按最右标签筛选规则；带有 `:is()`/`:where()` 的通用规则，以及包含很多选择器的同一条规则，仍让每个新行内元素走大量完整匹配。现在用完整目标元数据建立有界候选组：标签、ID、语义类、属性名、伪元素及其原始元素；递归预筛最右侧功能选择器的必要条件，并保留每条候选选择器的原始顺序和 specificity。

属性值、祖先、兄弟、位置、否定和实际交互状态继续由完整匹配器判断。相同属性名但不同值的元素可共用候选组，不能共用错误的匹配结果；临时对象地址不进入键。匹配完成后，完全相同的候选结果共享 Qt 存储。缓存命中仍要检查完整规则和继承值，不将指纹碰撞视为相等。

### 可见区优先与可取消预取

滚动同步构建实际可见区域及上下 80 px 的绘制保护区。停滚 120 ms 后再预取上下各 1.5 屏，每片最多两个块，4 ms 时间预算在块与块之间检查；单个不可拆分的大块仍可能超过预算。每片重新读取当前视口、文档和主题，滚动会重置等待时间，旧请求不会继续构建旧范围；隐藏视图停止预取，待完成的 resize 高度估计优先。

普通流式 lazy 布局空闲时保留最多 64 个详细顶层块，预取范围、光标、选区端点及正在编辑的 HTML 块受保护，必要时可以超过该数。远处详细布局被释放，但已测量高度、稳定位置索引和 AST 保留，返回时不先退回估计高度。同步释放其行内/伪元素视图及身份样式、配方 memo；结构块视图和祖先继续用于选择器导航。其他主题快照仍持有语义树时不删除其指针指向的数据。Eager/导出和根格式化上下文保留原行为。

共享最终样式、cascade/value memo 限制为 2048 项/桶，目标候选与匹配结果池限制为 512 个元数据键/桶，共享配方最多 512 项。变量指纹使用 128 个 Qt 共享表快照，避免小工作集反复哈希内嵌资源；公开变量表发生修改时会与快照分离。这些是数量边界，不代表整个进程的字节级内存预算。

新增诊断输出活动页的语义视图、身份缓存、最终样式、共享匹配组、配方和详细布局数量。回归覆盖跨元素共享与独立时间线、功能选择器祖先状态、属性值和大小写、动态否定、兄弟/位置条件、虚拟 ID/class 属性、伪元素原始元素，以及预算预取、远处回收、主题快照指针、反复返回、回收块局部编辑和全量排版/计数器对照。

## 第十四轮：热视口文字绘制只提交实际变化

### 从字形缓存继续追踪绘制覆盖

正文的 `TextLayout` 已启用 Qt 字形缓存，热滚动的主要问题不是再次塑形。`InlineLayout::paint()` 在接收宿主样式时，即使颜色与排版时的基础颜色完全相同，也为继承颜色的各段生成临时 foreground selections。Qt 6.11.1 的 `QTextLayout::draw()` 会逐个构建覆盖区域并绘制相关文字行；相同颜色仍会执行这条路径，已有的字形缓存不能省去这些重复绘制和裁剪。

### 生命周期和失效规则

- **草稿后台队列。** 每个窗口一条惰性串行 I/O worker，GUI 只捕获独立 PieceTable，正文展平、UTF-8 编码与提交在后台执行。每个 key 最多一个正在执行版本和一个最新待写版本；任务不访问 live session/tab/widget。只有成功完成通知确认 revision，失败留待重试。保存/丢弃/重载使旧 generation 失效，取消待写并排入 cleanup barrier；之后的新编辑排在清理之后。析构排空队列，不依赖 GUI 事件循环交付完成通知。
- **关闭与异常边界。** 清理异步返回，在途旧写入可能先提交再被清理删除，正常关闭可能等待存储。强杀未完成任务可能保留旧恢复状态；两个文件继续各自原子提交，未改成两文件事务。PieceTable 捕获共享 Qt 缓冲、复制 piece/prefix 向量，长编辑历史的 append-buffer detach 和高度碎片化仍可能增加复制成本。

- **菜单格式共享。** 一次 command snapshot 捕获六种格式，checked predicates 共用一份结果；分类刷新也用有作用域的快照，不跨光标、文档、设置刷新保留。
